#
# O que está aqui saiu da base de conhecimento e não volta. Três consumidores
# leem este arquivo, e nenhum deles tem uma cópia própria da lista:
#
#   1. `python -m app.knowledge.prune --list <este arquivo> [--apply]` apaga do
#      banco (produção incluída) os documentos, trechos e embeddings que casam.
#      Workflow "Administração do banco", ações `conhecimento_simular_remocao`
#      e `conhecimento_remover` (docs/13-deploy.md).
#   2. A ingestão (`app.knowledge.service`) pula todo arquivo que casa, mesmo
#      que ele reapareça no disco — a ingestão só acrescenta, e sem isto uma
#      cópia local esquecida devolveria o texto ao RAG.
#   3. A limpeza do histórico do git (docs/17-limpeza-historico-cerebro.md)
#      converte esta lista para o `--paths-from-file` do git-filter-repo.
#
# Formato: um caminho por linha, relativo a KNOWLEDGE_DIR (a pasta Cérebro/),
# com barra normal. Linha terminada em "/" é prefixo de pasta e casa tudo que
# está dentro dela; qualquer outra linha casa só aquele caminho exato. Linhas
# em branco e linhas que começam com "#" são ignoradas. A comparação normaliza
# Unicode (NFC), então um caminho gravado em NFD por um macOS também casa.
#
# Uma linha "sha256:<64 dígitos hexadecimais>" casa pelo CONTEÚDO: qualquer
# documento cujos bytes tenham esse SHA-256, em qualquer caminho. O banco e a
# ingestão leem essas linhas; a limpeza do histórico, que só entende caminho,
# as descarta (docs/17, passo 4).
